04 / API TESTING PROJECT
DUMMYJSON · POSTMAN · AUTOMATED ASSERTIONS

Validate the response.
Prove the result.

API Testing & Test Automation Using Postman

54 / 54TESTS PASSED0 failed · 0 errors · 0 skipped
PROJECT OBJECTIVE

What I tested

I built a reusable Postman collection to test REST API behavior across authentication, user profiles, product data, search, categories, invalid requests, and user posts. The aim was to verify expected responses using repeatable assertions rather than manual inspection alone.

TOOLS & SETUP

Reusable configuration

Tools: Postman, JavaScript assertions, DummyJSON REST API, Postman Collection Runner.

Collection: Testing Collection
Environment: API Testing Environment
Variables: Login, token, product_id

TEST STRATEGY

Positive & negative scenarios

Positive scenarios cover login, authenticated profile retrieval, product listing and details, product search, category filtering, and user posts. Negative scenarios cover incorrect or incomplete credentials, invalid endpoints, and a nonexistent product ID.

AUTOMATION

Assertions in Postman

Scripts check expected status codes, JSON responses, token presence after login, selected user and product fields, response arrays, and response-time thresholds where implemented. The token is stored in an environment variable for authenticated requests.

SCOPE & LIMITATIONS

DummyJSON is a public demonstration API. This project demonstrates functional API testing and selected automated assertions; it is not presented as a complete security assessment or a dedicated load-testing exercise.
